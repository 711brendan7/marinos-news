# note-publish — note への投稿

`note/` 配下のパイプライン（下書き生成 → 画像 → 投稿）を、**公開前の確認を挟んで**安全に回すための手順。
投稿自体は自動（`--auto`）だが、**投稿前に画像込みの下書きをユーザーが確認・承認する**ことを必須にしている。note は bot 行為を禁止しているため、少量・低速を守る。

## 前提

- 作業ディレクトリは `note/`。Python は `./venv/bin/python`。
- ログイン維持プロファイルは `note/.note_profile/`（初回のみ手動ログイン。**絶対にコミットしない**）。認証情報は `note/.env`（同じくコミット禁止）。
- 投稿系スクリプト（`publish_helper.py` ほか）と `style_guide.md` / `portfolio.md` は、リポジトリに無い環境がある（ローカル専用）。**無ければ存在しないものとして扱い、推測で代用せずユーザーに伝える。** 使うスクリプトは実行前に `--help` で引数を確認し、README に書かれていないフラグを当て推量で付けない。

## 手順

### 1. 投稿内容を確定する
- ユーザーが本文・下書きを渡していればそれを使う。無ければ `output/` の下書きを確認し、どれを出すか聞く。ネタから作る場合は `draft_generator.py`（Claude Code CLI）で `style_guide.md` に沿って生成する。
- `style_guide.md` を読む（ペルソナ・文体・タイトルの型・著作権ルール）。
- `portfolio.md` を読み、**数字（利回り・金額・件数など）は実績台帳と一致させる**。台帳に無い数字は書かない／ユーザーに確認する。体験談・実績が手元に無い箇所は、空欄で止めず**数字や個人の実績を使わない一般論に書き換えて**先へ進める（ユーザーが後から体験を足せる）。同テーマの既出記事があれば二重投稿になるので指摘する。

### 2. 見出し画像（ChatGPT で作る）
- 画像は **ChatGPT で生成**する（`generate_image.py` / Codex は使わない）。
- 記事のタイトル・要点から、ChatGPT に貼る画像プロンプトを書いて渡す（note の見出し画像は横長 1280×670 前後が目安。文字入れはタイトルと一致させる）。
- 生成した画像のファイルパスをユーザーから受け取る（`note/output/` に置いてもらう）。ChatGPT を操作できるブラウザツールが使える場合でも、ログインや規約確認はユーザーに任せ、勝手に進めない。
- 受け取った画像は Read で実際に目視し、タイトルの誤字・崩れた文字・著作物っぽい要素がないか確認する。問題があればプロンプトを直して作り直してもらう。

### 3. ハッシュタグ
- 記事ごとにハッシュタグを決め、**本文と一緒に投稿する**。数は 5 個前後を目安に、本命ニッチ（例: `#ボロ戸建て` `#大家` `#不動産投資`）＋記事固有のタグ。`style_guide.md` にタグのルールがあればそちらを優先。
- タグの渡し方は `publish_helper.py` の実装に依存する。`--help` と記事ファイルの形式を確認して合わせる。**タグを渡せない仕様だった場合は推測で回避せず、ユーザーに伝えて方法を決める。**

### 4. 公開前チェック
- タイトルが style_guide の型に沿っているか。
- 他者の文章・画像の無断転載がないか（引用は出典明記）。
- 見出しは `■` 始まりの行で書く（貼り付け時に自動で見出しへ変換される）。
- 有料記事の場合は価格・無料部分の境界（有料ライン）を確認する。

### 5. 下書きの確認（必須・画像込み）
投稿前に、**画像を含めた下書き全体**をユーザーに見せて承認をもらう。
- `note/output/` にプレビュー用の Markdown（タイトル／ハッシュタグ／価格／公開方法／本文／画像への参照）を書き出し、画像ファイルと一緒に `SendUserFile` で渡す。
- チャットにも「タイトル・タグ・画像・本文の要点・公開方法」を要約して載せる。
- **明示的な OK が出るまで投稿しない。** 修正指示が出たら直して、もう一度同じ形で見せる。OK は今回の記事・今回の内容に対してのみ有効で、他の記事や修正後の内容には流用しない。

### 6. 自動投稿する
承認後は **完全自動**（`--auto`）で、本文・画像・ハッシュタグを入れて公開まで行う。

| 目的 | 使うもの |
|---|---|
| 即時公開（既定） | `./venv/bin/python publish_helper.py --auto <記事ファイル>`（画像・タグの渡し方は `--help` で確認） |
| 日時指定 | `scheduled_publish.py`（note の予約投稿はプレミアム限定のため、これで代替） |

- 承認した内容と実際に投稿する内容（本文・画像・タグ）が一致していることを実行直前に確認する。
- 未ログインで終了した場合は、ユーザーに手動ログインを依頼する（`--headful` 等でブラウザを見せる）。CAPTCHA・認証の回避やリトライの連打はしない。
- 失敗しても自動で再投稿を繰り返さない。部分的に公開されている可能性があるので、まず note 側の状態をユーザーと確認する（重複公開防止）。
- 1 回の依頼で投稿するのは承認された記事のみ。大量の連続投稿はしない。

### 7. 公開後
- 公開された記事の URL をユーザーに報告する（画像・タグが反映されているかも確認して伝える）。
- `portfolio.md` があれば、記事のタイトル・URL・日付・使った数字を追記する提案をする（勝手に確定しない）。
- 本文の差し替えは `fix_publish.py body`、タイトル一括変更は `migrate_titles.py`、末尾定型の削除は `strip_closing.py`。
- `retire_merged.py` / `delete_dupes.py` は**記事を削除する取り返しのつかない操作**。対象一覧を見せて、個別に明示承認を得てから実行する。

## やらないこと
- 画像込みの下書き確認なしの公開、ユーザー承認なしの削除。
- `.env` / `.note_profile/` / `*.log` のコミットや内容の出力。
- 大量・機械的な連続投稿（note の規約違反＝アカウント凍結リスク）。
- `style_guide.md` / `portfolio.md` にない実績数字のでっち上げ。
